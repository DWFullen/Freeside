# Placeholders

Everything the code stubs out because we don't have the account, key or decision yet. Each entry is marked `PLACEHOLDER(<id>)` at the point in code or configuration where the real value plugs in.

**CI keeps this file and the code in step** (`tools/ci/check-placeholders.sh`, run by the `repo-checks` job). The last column, **In code**, says whether the marker exists yet:
- `yes`: `PLACEHOLDER(<id>)` must appear in the code.
- `no`: it must not appear yet. The PR that adds the marker sets the row to `yes` in the same change.

Every marker in the code must have a row. Markdown files, `docs/` and `tools/ci/` are not scanned.

Rules (`docs/plans/phase-0.md`, ADR 0012, ADR 0013):

- A stand-in `Fake` implements `IFakeService` and is registered with `AddFake<TService, TFake>()`. It is allowed only when `Bitcoin:Network=regtest`; any other network fails at startup.
- Secret values never go in the repo, in Terraform state or in plaintext pipeline variables. Secrets are listed here by **name** (Key Vault secret name, config key); an operator sets the value.
- Non-secret identifiers (tenant, subscription and client IDs) also stay out of the repo, because the repo is public. They are passed as GitHub variables or `TF_VAR_*` environment variables.
- BTCPay runs on the operator's Start9 node, outside Azure (ADR 0013). Until a BTCPay placeholder is filled for an environment, the BTCPay rail's breaker stays open there. It never falls back to a fake.
